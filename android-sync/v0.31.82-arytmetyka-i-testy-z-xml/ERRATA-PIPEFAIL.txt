ERRATA do wydania 0.31.82 — sekcja 3 (pipefail)
===============================================

Ten folder zawiera wydanie 0.31.82 razem z README-WGRANIE.txt. Sekcja
„3) Dziura, którą przy okazji zamknąłem: | tee maskowało kod wyjścia" tego
README jest NIEPRAWDZIWA. README zostawiam bez zmian, bo ta wersja jest
w środku paczki ZIP 0.31.82 — prostuję tutaj.

Co README twierdzi (błędnie)
----------------------------
  „Oba kroki Gradle kończyły się potokiem ./gradlew ... 2>&1 | tee build.log.
   Domyślny shell runnera to bash -e BEZ pipefail, więc kod wyjścia kroku
   brał się z tee, a nie z Gradle — nieudany build albo czerwony test mógł
   skończyć się zielonym krokiem."

Jak jest naprawdę
-----------------
Runner GitHuba uruchamia `run:` poleceniem

  bash --noprofile --norc -e -o pipefail <skrypt>

(actions/runner, ScriptHandlerHelpers.cs) — czyli pipefail jest DOMYŚLNIE.
`| tee` nie maskowało kodu wyjścia Gradle. Zielony run 0.31.81 dowodził
więc, że testy przeszły, a nie tylko że się wykonały.

Błąd wziął się z powtarzania obiegowej opinii o „bash -e" z zakładki „shell"
w dokumentacji, bez sprawdzenia, jaki shell runner bierze, gdy `shell:`
nie jest podane. Nie sprawdziłem tego ani w kodzie runnera, ani próbą.

Co zostaje
----------
  • `set -o pipefail` w obu krokach zostaje (działa też przy `shell: sh`
    i przy ręcznym uruchomieniu), ale BEZ fałszywego uzasadnienia,
  • komentarze w workflow poprawione: nie twierdzą już, że zamknięto dziurę,
  • brama nie sprawdza już „liczby wystąpień" — wymaga `set -o pipefail`
    w tym samym kroku co `| tee` (komentarz nie wystarcza).
