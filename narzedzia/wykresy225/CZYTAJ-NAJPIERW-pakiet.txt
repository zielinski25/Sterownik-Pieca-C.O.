Sterownik CO — CAŁY PROJEKT ANDROIDA, wersja 0.31.45
====================================================

To jest KOMPLETNY projekt (Gradle + wszystkie pliki źródłowe), gotowy do
otwarcia na dowolnym komputerze z Android Studio. Nie trzeba nic doklejać
ani podmieniać — wersja 0.31.45 jest już w środku.

CO JEST W ŚRODKU
----------------
- cały kod aplikacji (96 plików .kt + testy + zasoby + dźwięki alarmów),
- gradle wrapper (Gradle 8.9) — Gradle sam się dociągnie,
- versionName = "0.31.45", versionCode = 31045,
- zbuduj.ps1 (budowanie jednym poleceniem),
- folder ZMIANY-KODU z diffem każdej zmiany (do wglądu),
- SHA256SUMS.txt — suma kontrolna każdego pliku .kt (patrz niżej).

NAJWAŻNIEJSZE: CO WRÓCIŁO
-------------------------
1) USTAWIENIA → „Bufor offline"
   Przełącznik zapisu na flash centrali + liczniki od startu.
   Wymaga firmware v3.54.0 lub nowszego; na starszym jest nieaktywny
   z wyjaśnieniem.
2) KAFELEK „SERWO" W PROCENTACH
   „klapa 42%" + „syberek 17%" w podpisie, pigułka AUTO / RĘCZNY,

3) DŹWIĘKI ALARMÓW z aplikacji + synchronizacja z centralą.
4) TERMINAL DLOG sam się zatrzymuje po 5 min bez dotykania ekranu.
5) PAMIĘĆ HISTORII w telefonie — dociągane są tylko brakujące przedziały.

JAK ZBUDOWAĆ POLECENIEM (najszybciej)
------------------------------------
W folderze projektu (tym z settings.gradle.kts) uruchom jedną komendę:

  powershell -ExecutionPolicy Bypass -File .\zbuduj.ps1

Skrypt sam znajduje Javę 17–22, sam znajduje Android SDK, zapisuje
local.properties, buduje APK, kopiuje je do Pobranych jako
SterownikCO-v0.31.45-debug.apk i wypisuje komendę do instalacji.

JEŻELI CHCESZ ZBUDOWAĆ RĘCZNIE
------------------------------
  .\gradlew.bat :app:assembleDebug --console=plain
Plik APK: app\build\outputs\apk\debug\app-debug.apk

UWAGA — Java 25 nie zadziała
----------------------------
Android Studio 2026 ma w środku Javę 25. Gradle 8.9 nie obsługuje Javy 25
i kończy się mylącym błędem:

  * What went wrong:
  25.0.3

Ta liczba to po prostu wersja Javy, której próbował użyć Gradle.
Rozwiązanie: budować na Javie 17–21 (np. Temurin 21) albo po prostu użyć
zbuduj.ps1, który robi to sam. NIE ustawiaj JAVA_HOME na
"C:\Program Files\Android\Android Studio\jbr".

Druga typowa przeszkoda to brak wskazania Android SDK:

  SDK location not found. Define a valid SDK location with an
  ANDROID_HOME environment variable or by setting the sdk.dir path ...

zbuduj.ps1 szuka SDK sam (ANDROID_HOME, %LOCALAPPDATA%\Android\Sdk,
C:\Android\Sdk, a na końcu po pliku adb.exe) i zapisuje local.properties.
Jeśli brakuje platformy android-35, skrypt to wypisze.

JAK ZBUDOWAĆ KLIKAJĄC
---------------------
1. Android Studio > File > Open... > wskaż folder rozpakowany z tego ZIP-a
   (ten, w którym leży plik settings.gradle.kts — NIE folder app).
2. Studio samo dociągnie Gradle 8.9 i biblioteki (potrzebny internet,
   pierwszy raz może potrwać kilka minut).
3. Jeżeli zapyta o JDK — wybierz JDK 17 lub 21.
4. Build > Build Bundle(s) / APK(s) > Build APK(s).

JAK ZAINSTALOWAĆ NA TELEFONIE
-----------------------------
- Przez kabel: włącz w telefonie „Debugowanie USB" i użyj przycisku Run,
  albo:
    adb.exe install -r "app\build\outputs\apk\debug\app-debug.apk"
- Bez kabla: przenieś APK na telefon (kabel, Dysk Google, Telegram) i
  otwórz go w telefonie — trzeba zezwolić na „instalację z nieznanych
  źródeł".
- Nadinstalowanie na starszą wersję działa, dane i ustawienia zostają.

PO CZYM POZNASZ, ŻE MASZ WŁAŚCIWĄ WERSJĘ
----------------------------------------
Ustawienia → lista kafelków. Musi być „Bufor offline"
(między „Czujnik dymu" a „Data i czas").
Pulpit → kafelek SERWO pokazuje procenty: „klapa 42%".

JAK SPRAWDZIĆ, CZY PLIKI DOJAZDY BEZ USZKODZENIA
------------------------------------------------
W folderze projektu:

  Get-FileHash -Algorithm SHA256 -Path (Get-ChildItem -Recurse -Filter *.kt).FullName

albo porównaj pojedynczo z plikiem SHA256SUMS.txt. Jeśli któraś suma się
nie zgadza, plik jest uszkodzony przy kopiowaniu — pobierz paczkę jeszcze
raz, zamiast poprawiać kod.

JEŚLI COŚ SIĘ NIE ZBUDUJE
-------------------------
Najczęstsze przyczyny:
- otwarty zły folder (trzeba ten z settings.gradle.kts),
- brak internetu przy pierwszym otwarciu (Gradle nie dociągnął bibliotek),
- brak JDK 17–21 (File > Settings > Build > Gradle > Gradle JDK).

Jeżeli Gradle wypisze błąd inny niż powyższe — prześlij dokładnie tę
linijkę, w której jest napisane „e: file:///...: (N, M) Unresolved
reference: ...". To wystarcza do poprawki.
